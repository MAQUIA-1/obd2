# Classic SPP 폴링 수집 결과

- 날짜: 2026-11-19
- 대상: 사용자 확인 기준 **2015년식 LF 쏘나타 하이브리드**
- 전원 상태: 사용자 READY 표시 켜짐 응답. 초기 수신 기어 P, 속도 0.
- 연결: 노트북 BlueZ Profile1 → Classic SPP → OBDII 어댑터.
- 범위: 읽기 전용 PID 조회. 차량 제어·코드 삭제·세션 변경은 하지 않았다.

## 1. 기본 수집 결과

`captures/poll-baseline-01/`에서 약 20초간 PID 9종을 순차 조회했다. **107회 중 107회가 요청한 ECU·서비스·PID와 일치하고 완전한 응답으로 해석됐다.** 화면 항목은 11개다. 이는 응답 형식과 수집 경로 확인이며 전체 센서 정확도를 독립 측정한 결과는 아니다.

| 정보 | 마지막 수신값 | 유효 응답 | 요청 응답 중앙값 | 실제 갱신 간격 중앙값 |
|---|---|---|---|---|
| 속도 | 0 km/h | 31/31 | 103 ms | 0.65 s |
| RPM | 0 rpm | 18/18 | 103 ms | 1.12 s |
| 셀렉터 기어 | P | 18/18 | 188 ms | 1.14 s |
| HV 전류·SOC·전압 | 1.3 A / 55.5% / 273.9 V | 15/15 | 186 ms | 1.30 s |
| 조향각 | -5.7° (정면 정렬 요청 전) | 17/17 | 124 ms | 1.11 s |

요청 응답 시간은 헤더 변경 시간을 제외한 호스트 기준 시간이다. 실제 갱신 간격은 이번 폴링 스케줄에서의 결과이며 어댑터의 최대 성능이나 BLE 대비 성능을 의미하지 않는다. 현재 속도 갱신 설정은 300ms지만 순차 작업의 대기로 실제 간격은 더 길다. UI에 사용할 목표 간격은 이 결과를 바탕으로 조정한다.

## 2. 조향 동작 확인

`captures/poll-steering-02/`에서 조향 PID만 113회 수집했고 113회 모두 형식 검증을 통과했다.

- 사용자 정면 유지 확인 후 최근 수치는 약 -3.0~-3.1°.
- 왼쪽 약 90도 조작 요청 및 사용자 유지 확인 시 약 -84.9~-85.1°.
- 방향과 대략적인 변화량이 실제 조작을 따라가는 것을 확인했다.
- 사용자가 추가 조향 시험이 불필요하다고 하여 기록을 중단했다. 우측·정면 복귀 반복 시험이나 정밀 각도 보정까지 완료한 것으로 보고하지 않는다.
- 대화 확인 시점은 정확한 조작 시작 시각과 다르다. 안내 및 확인 마커는 events.jsonl에 보관했다.

첫 조향 세션 `poll-steering-01`은 BlueZ에서 SPP 스트림을 받지 못해 실패했고 수신값이 없다. 스캐너의 남은 연결을 명시적으로 종료하고 두 번째 세션을 열어 해결했다. 이 실패와 정상 세션은 별도로 보존했다.

## 3. 추가 데이터 후보: 새 요청 없이 기존 패킷에서 추출

기본 수집에서 이미 받은 BMS·TCM 패킷을 공개 OBDb Sonata 정의와 대조했다. 총 41개 필드 후보를 `additional_candidates.json`에 저장했다. 기존 11개와 중복되는 필드도 있으므로 41개가 모두 새로운 기능이라는 뜻은 아니다. 모든 추가 필드는 독립 검증 전 후보 상태다.

| 후보 | 마지막 패킷에 정의를 적용한 값 | 현재 판단 |
|---|---|---|
| 배터리 최고·최저 온도 | 각각 15°C | 보조 정보 후보, 별도 온도 기준과 비교 전 |
| BMS 보조 전압 | 14.6 V | 제어 모듈 전압 14.784 V와 측정원·분해능이 다름 |
| 변속기 오일 온도 | 28°C | 정차 상태에서 타당해 보이는 후보, 독립 확인 전 |
| BMS 메인 릴레이·점화 비트 | 각각 1 | READY와 동일 신호라고 단정하지 않음 |
| 가속페달 상대 위치 | 0% | 실제 페달 조작 시험 전 |
| 브레이크 페달 필드 | 원시 해석값 240 | 불리언으로 해석하지 않음; 비트 의미 미확정 |
| 배터리 허용 충·방전 전력, 누적 충·방전량·에너지 등 | 후보 JSON에 보관 | 정의·차종 적용성 추가 검토 필요 |

BMS 정의에는 OBDb의 dbg 표기가 있고 Niro 이름이 남아 있는 필드가 있다. LF 차량에 완전히 검증된 공식 신호표로 취급하지 않는다. 추가 값의 추출은 기존 응답을 재사용하므로 차량 요청량은 증가하지 않았다.

## 4. 재현 도구와 근거

- `tools/obd_poll.py`: Classic 순차 폴링. 원시 BLE/Classic 공통 기록기를 재사용하며 타임아웃은 세션 중단, 잘린 프레임과 다른 ECU 응답은 유효값으로 처리하지 않는다.
- `tools/obd_summary.py`: 수집 결과 통계와 제한된 Mode 21 추가 후보의 오프라인 추출.
- `captures/poll-baseline-01/raw.jsonl`: 원시 전송 및 수신.
- `captures/poll-baseline-01/transactions.jsonl`: 요청·응답·해석·항목별 시각 및 소요 시간.
- `captures/poll-baseline-01/summary.json`: 항목별 통계.
- `captures/poll-baseline-01/additional_candidates.json`: 출처와 미검증 상태를 포함한 추가 후보.
- `captures/poll-steering-02/transactions.jsonl`, `events.jsonl`: 조향값 및 조작 마커.
- 공개 정의 버전은 `research/sources_manifest.json` 참고. 원시 로그는 Git 제외 대상이다.

프레임 순서·응답 길이·부호 있는 전류·셀렉터·연결 스트림 등을 확인하는 로컬 테스트 총 10개가 통과했다. 오프라인 추가 후보 추출기의 모든 신호 의미가 테스트로 검증됐다는 뜻은 아니다.

## 5. 아직 하지 않은 검증

- R/N/D/M 셀렉터 변화 재확인, 주행 속도·엔진 RPM의 동적 변화.
- 추가 필드의 독립 검증, 방향지시등·문·공기압 등 새로운 PID 확보.
- 장시간 안정성·전원 꺼짐 후 복구·연속 재연결.
- 스마트폰 Chrome 및 DeX의 Web Serial 실연동.

현재까지의 수집으로 기존 대시보드의 주요 값들을 Classic 폴링으로 가져올 수 있다는 근거를 확보했다. 추가 현장 조작은 제품에 꼭 필요한 미확인 항목에 한정한다.
