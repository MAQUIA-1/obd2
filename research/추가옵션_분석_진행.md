# 추가 옵션 데이터 분석 진행

2026-11-19. 기본 11개 항목 검증 이후의 문·등화·브레이크 등 확장 조사 기록이다.

## 운전석 문 개폐 후보

- 요청 7A0 `22B005`, 응답 7A8 `62B005`.
- 서비스·DID 3바이트를 제거한 데이터의 **0부터 센 byte 4, bit 2 (mask 0x04)**.
- 닫힘 `379a100208400800` → 열림 `379a10020c400800` → 닫힘 `379a100208400800`.
- `body-controls-01/events.jsonl` 사용자 확인 이후 1초 및 다음 안내 직전 1초를 제외하면 닫힘 1건 / 열림 3건 / 복귀 닫힘 8건이 모두 같은 비트 패턴이다.
- 모든 12개 그룹의 안정된 닫힘→열림→닫힘 비트를 대조하면 이 비트만 0→1→0 조건을 만족한다. 비교 자료는 `captures/body-controls-01/door-comparison.json`.
- 판정: 운전석 문 조작과 연관된 유력 후보. 이 첫 세션에서는 1회 개폐뿐이며 운전석 전용/문 통합/실내등 등 연동 상태인지 구분하지 못했다. 문별 비교 또는 재현 시험으로 의미를 더 좁힌다.

## 공개 정의 대조

1. [OBDb Sonata 원본](https://github.com/OBDb/Hyundai-Sonata/blob/main/signalsets/v3/default.json): 770/BC03 문, BC05 비상등, BC08 좌우 깜빡이는 `filter.from=2021` 정의다. 2015 LF에 그대로 적용하지 않는다. 기존 `dashboard-probes-01`에서 해당 요청은 `7F2231` 응답이었다. 따라서 주소에 응답이 없다는 뜻이 아니라 해당 DID 요청이 거부된 기록이다.
2. [eNiroDashboard 개발자 원본](https://github.com/HK-Moebius/enirodashboard/blob/release/car_debug_obd2_kia.h): 7A0 B001~B00E의 응답 예시를 제공하지만 문·깜빡이의 비트 정의는 제공하지 않는다. 이번 B005 후보는 이 소스가 확정한 의미가 아니라 실차 조작에서 찾은 결과다.
3. OBDb Sonata는 **7A0/B008의 브레이크 스위치**와 **7A0/B00C의 열선 핸들**을 제시한다. 두 DID 모두 이번 LF에서 정상 응답이 이미 있다. 따라서 새 주소 스캔 없이 조작 전후 비교 가능한 다음 후보로 잡는다. OBDb의 dbgfilter는 검증 범위에 대한 메타데이터이며 차량에서의 의미를 보증하지 않는다.
4. 7C6/B002 계기판은 응답했으나 확보 데이터가 7바이트뿐이다. OBDb 주행거리 정의는 데이터 bit 48부터 24비트가 필요해 현재 응답 길이로는 부족하다. 짧은 응답에 억지로 공통 주행거리 공식을 적용하지 않는다.

## 깜빡이 현황과 다음 순서

`body-controls-03`에서 좌·우·비상등 ON/OFF 비교 완료. 현재 B0 그룹에서 확정 신호 없음. 자세한 결과는 `BCM_깜빡이_비교_결과.md` 참고. 공개 자료 검색에서도 LF용으로 직접 확인된 대체 깜빡이 PID·비트 정의는 아직 찾지 못했다. CAN 방송 DBC는 PID 응답 비트에 옮겨 적용하지 않는다.

다음 실험은 B005 문 후보 재현 및 B008 브레이크 스위치 비교를 우선한다. 선택한 DID만 조회하도록 도구에 `--dids`를 추가해 12개 순차 요청에 따른 약 2초 간격을 줄인다. 브레이크는 P·주차브레이크를 유지하고 밟음/놓음만 비교하며 기어·전원 전환은 요구하지 않는다. 열선 핸들은 장착 여부를 확인한 뒤 선택적으로 검증한다.

오프라인 분석 후 `captures/body-options-04`에서 B005/B008/B00C 3개 그룹 수집을 시작했고 정상 응답을 확인했다. 후속 조작은 안내·사용자 확인 마커로 분리한다. 기존 로컬 테스트 10개는 socketpair 사용을 허용한 환경에서 통과했다.

## 사용자 우선순위 변경 및 등화 시험

운전석 문 재시험에서 `body-options-04`의 B005가 열림 `...0c...` → 닫힘 `...08...`으로 다시 복귀했다. 다른 문 구분은 미검증. 사용자는 브레이크·열선보다 깜빡이 또는 등화류를 우선 요청했다. 3개 그룹 수집을 종료하고 `body-lights-05`에서 기존 12개 그룹을 수집한다. 아직 조작하지 않은 수동 미등·하향등·상향등을 OFF 기준과 각각 비교한다. AUTO 위치 및 실제 램프 점등은 스위치 위치와 구분해 기록한다. 공개 자료 조사에서 LF 전용 등화 비트 정의나 SJB의 확정 대체 DID는 확보하지 못했으므로 임의 주소 탐색 대신 응답 확인 그룹의 조작 비교부터 진행한다.

## 최종 범위 및 종료 상태

`body-lights-05`에서 OFF → 미등 ON → OFF를 비교했다. B005 데이터 byte 4의 mask 0x20과 B00D 데이터 byte 4의 mask 0x02가 켜졌다가 복귀했다. 데이터는 각각 `379a100208400800` → `379a100228400800` → `379a100208400800`, `fcfee000000004` → `fcfee000020004` → `fcfee000000004`였다. 미등 전용 비트인지 다른 등화 상태와 공유하는지는 미확인이다.

하향등 ON 안내 후 사용자가 범위를 기존 항목으로 확정하면서 추가 시험을 중단했다. 하향등·상향등은 사용자 ON 확인과 검증이 없었다. 브레이크·열선 핸들 조작 시험도 하지 않았다. 모든 수집 프로세스는 종료했고, 원시 로그는 로컬 captures에 보존했다. 제품 범위는 기존 기본 11개 항목이며 문·미등은 후속 후보로 남긴다. 웹 개발 인계 및 실제 응답 예제는 `웹개발_인계.md`와 `research/fixtures/verified-poll-examples.json`에 있다.
