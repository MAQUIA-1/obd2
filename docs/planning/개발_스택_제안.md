# 개발 스택 제안

2026-11-19 · 초기 설치·구현 전 제안과 검토 이력. React 프론트엔드 과제, Android Chrome + DeX, 세로 화면을 기준으로 한다.

현재 기준: 흰 배경의 미니멀 UI + 사용자 제공 LF 쏘나타 GLB + P 회전형 개러지·R 버드아이뷰의 후방 조향 점선 가이드. 기성 로우폴리와 자체 라인 시안은 미채택이다. 바퀴 회전·조향 애니메이션은 필수가 아니다. 후반의 외형 변경 절은 검토 이력이며 최종적으로 '사용자 제공 모델로 전환'이 적용된다.

## 추천 구성

| 역할 | 제안 | 선택 이유 |
|---|---|---|
| 화면·언어 | React 19 + TypeScript | 기존 과제 조건 유지. PID 값·상태·단위와 장면 입력의 타입을 명확히 구분 |
| 빌드·개발 서버 | Vite 안정 버전 | 브라우저에서 동작하는 대시보드에 적합. 정적 빌드 배포 |
| 스타일 | Tailwind CSS 4 + CSS 변수 | 흰색 배경, 검정 텍스트, 일정한 여백·타이포·반응형 배치를 직접 설계 |
| 3D 차량 | Three.js + React Three Fiber 9 + 호환되는 Drei | 같은 차량을 주차 버드아이뷰와 주행 후방 시점에서 표현. 조향 점선·바닥 흐름·카메라 전환 |
| UI 애니메이션 | Motion for React | 하단 패널 진입·퇴장, 설정 미리보기, 레이아웃 전환 |
| 3D 애니메이션 | R3F useFrame + Three.js 객체 | 차량·바퀴·바닥·카메라를 프레임 간 시간에 맞춰 갱신. React 상태를 매 프레임 갱신하지 않음 |
| 상태 관리 | Zustand | 통신 데이터·연결 상태·편집 설정을 필요한 부분만 구독 |
| 설정 보존 | localStorage, Zustand persist | 테마·차량색·위젯·모션 설정만 저장. 현재 속도·기어 등 실시간 값은 복원하지 않음 |
| 차량 통신 | Web Serial + Bluetooth Classic SPP | 이번 실차에서 확인한 Classic PID 폴링 경로 유지 |
| 차량 모델 | 사용자 제공 LF 쏘나타 GLB | 텍스처 내장, 모델 구조 검사 완료. 브라우저 표시 검증 필요 |
| 검증 | Vitest + TypeScript 타입 검사 + ESLint | 저장한 실제 응답으로 파서·해석식 검증, 모드 전환·수신 지연 처리 검증 |
| 패키지 관리 | npm + package-lock.json | 버전 조합과 재현 가능한 설치를 한 가지 방식으로 유지 |
| 배포 | HTTPS 정적 호스팅 | 연결·처리·화면이 스마트폰 브라우저에서 실행되므로 첫 버전에 서버·DB가 필요하지 않음 |

패치 버전은 프로젝트 생성 시 공식 안정 버전과 peer dependencies를 확인한 후 lockfile에 고정한다. React Three Fiber 공식 설치 문서 기준 React 19는 Fiber 9와 짝을 이룬다. next 문서에 있는 Fiber 10/WebGPU 실험 구성을 초기 기본값으로 택하지 않는다. 렌더링은 WebGL 기반으로 시작한다. 개발용 Node는 선택한 Vite·Vitest의 요구 버전을 만족하는 지원 중인 LTS를 사용한다.

## 화면 계층

```text
React + Tailwind / HTML
  ├─ 상단 연결·시각·외기온
  ├─ 큰 속도·기어
  ├─ Three.js 차량 장면 (Canvas 1개)
  │    ├─ P: 정수직 버드아이뷰, 조향 점선 가이드
  │    └─ D/R/N/M: 차량 뒤 시점, 차속 기반 바닥 모션
  └─ 보조 정보·하단 상세·설정 패널
```

숫자와 버튼은 HTML로 그려 선명한 글자와 접근성을 유지한다. 차량 모델과 바닥·조명만 3D로 처리한다. 화면 전체를 캔버스로 만들지 않는다. 같은 차량과 Canvas를 유지하면서 카메라·오브젝트를 변경한다.

Motion은 HTML 패널과 버튼의 전환을 담당한다. 3D 바퀴·카메라에는 별도의 프레임 갱신을 사용한다. 중복 애니메이션 엔진을 추가하지 않는다.

## 데이터 계층

```text
실차 Serial 공급기 / 데모 공급기
          ↓ 공통 차량 데이터 형식
     항목별 값·수신 시각·유효 상태
          ↓ Zustand
       숫자 UI / 차량 장면
```

TypeScript로 ELM 명령 순차 처리·완료 프롬프트 수신·ISO-TP 재조립·PID 해석을 구현한다. 기준은 tools/obd_poll.py이며 Linux BlueZ 코드를 브라우저에서 실행하는 것은 아니다.

실차와 데모는 동일한 데이터 형식을 사용한다. 저장한 research/fixtures/verified-poll-examples.json은 파서 검증용이다. 주행 장면 시연에 사용하는 가변 속도·기어는 별도의 데모 공급기에서 만들고 화면에 데모 상태를 유지한다.

상태 저장은 telemetry / connection / preferences 정도로 나눈다. UI는 필요한 항목만 구독하고 3D 장면은 최신 입력을 읽어 보간한다. 속도·기어·각도의 유효성 및 stale 상태는 장면 밖에서 결정한다. 연결 해제 시 바닥 흐름과 바퀴 회전을 멈추고 숫자는 미수신 상태로 표시한다.

## 차량 모델 요구 사항

- 사용자 제공 `design/models/sonata-lf/sonata15.glb`를 사용한다. 원본 압축 파일도 함께 보존한다.
- 주차 버드아이뷰에서 차체 형태와 조향 점선 가이드가 선명하게 보여야 한다.
- 바퀴 조향·회전은 첫 버전에서 필수가 아니므로 바퀴 분리·피벗 정리를 선행 조건으로 두지 않는다.
- 실제 핸들 각도는 숫자로 표시하고 점선은 방향·상대적인 꺾임을 나타낸다. 정밀 주차 궤적으로 표시하지 않는다.
- 모델 구조 검사 결과는 inspection.json에 있다. 브라우저 외형·성능은 검증 전이며 원본 출처·라이선스는 아직 기록되지 않았다.

## 디자인 조건

사용자 지정 방향은 **테슬라처럼 밝고 미니멀한 화면**이다. 흰색·연한 회색 배경, 검정 중심 텍스트, 큰 속도, 절제된 강조색, 얇거나 없는 카드 경계로 구성한다. 과한 유리 효과·네온·어두운 SF 패널을 기본으로 삼지 않는다.

기존 SVG/PNG 스토리보드는 위치와 동작을 설명하는 개념도이며 최종 디자인이 아니다. 흰색 배경의 실제 시각 시안은 별도로 제작한다. 스타일 라이브러리는 디자인을 강제하는 대형 컴포넌트 모음보다 Tailwind와 직접 구성한 소수의 공통 컴포넌트로 시작한다.

## 첫 버전의 검증 기준

1. 저장한 9종 응답의 ISO-TP payload와 11개 해석값이 Python 기준과 일치한다.
2. 데모에서 P↔D 전환, 0 속도 정지, 조향, stale·disconnect를 재현한다.
3. 세로 화면에서 숫자·버튼·차량·조향 가이드가 겹치거나 가려지지 않는다.
4. 사용자 설정만 새로고침 후 복원하고 실차 값은 새 응답 전까지 '--'로 둔다.
5. 실제 스마트폰·DeX에서 연결과 렌더링 성능을 확인한다. 고사양 PC의 결과로 대신하지 않는다.

Web Serial의 Android Bluetooth RFCOMM 지원은 Chrome 138 공식 릴리스 문서에 있다. 이 사용자 스마트폰·어댑터·DeX 조합의 성공을 의미하지는 않으므로 최종 실차 연결은 검증이 남아 있다. 개발 중 스마트폰에서 네트워크 IP의 HTTP 개발 서버를 여는 것만으로 보안 컨텍스트 조건이 충족되는 것은 아니다. 목표 스마트폰 시험에는 HTTPS 제공 경로를 사용한다.

## 차량 외형 방향 수정

후속 사용자 피드백: 폴리곤 면이나 사실적인 3D 재질보다 **아웃라인 중심의 그래픽**을 선호한다. 기성 Quaternius 후보는 미채택이며 매끈한 외곽선·창문선·바퀴선 위주의 자체 그래픽을 우선 검토한다.

`design/vehicle-line-art-concept.svg`는 직접 그린 버드아이뷰·사선 시점의 스타일 초안이다. PNG도 함께 제공한다. 이 파일은 2D 벡터 시안으로 실제 3D 모델이나 연속 카메라 전환 구현이 아니다. 앱에서는 SVG 기반 두 상태 전환으로 시작하거나, 같은 선 표현을 내는 단순 3D 구조를 직접 만들어 카메라를 연결할 수 있다. 전체 삼각형을 드러내는 와이어프레임 대신 외곽과 필요한 윤곽선만 표시한다. 최종 렌더링 방식은 시각 방향 검토 후 결정한다.

## 사용자 제공 모델로 전환

사용자가 LF 쏘나타 GLB를 제공했다. 사용 대상은 `design/models/sonata-lf/sonata15.glb`이며 3.02MiB, 약 4.65만 삼각형이다. GLB 구조 및 외부 파일 의존성 검사는 통과했고 실제 렌더링은 미확인이다. 직접 제작 라인 그래픽·Quaternius 후보는 채택하지 않는다.

바퀴를 움직이는 대신 버드아이뷰에 조향 반응 점선 가이드를 그리는 방향으로 변경했다. 3D 바닥 위 선 또는 SVG/HTML 오버레이 중 실제 화면에서 읽기 쉬운 방식을 선택한다. 정확한 궤적 계산이 아닌 상대 조향 가이드로 구현하므로, 바퀴 분리·정밀 피벗 준비는 첫 버전의 필수 작업에서 제외한다.

현재는 이 구성을 바탕으로 React 웹 프로토타입을 구현했다. 설치 버전과 개발 명령은 [개발 문서](../development.md), 최신 화면 동작과 검증 범위는 [대시보드 구현](../design/대시보드_구현.md)을 참고한다.
