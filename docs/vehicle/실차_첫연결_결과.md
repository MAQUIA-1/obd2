# LF 쏘나타 하이브리드 첫 연결 결과

- 날짜: 2026-11-19
- 사용자 확인: P·주차브레이크 유지 질문에 READY 표시 켜짐 응답.
- 조작 실험: 아직 요청하지 않았다.

## 확인된 사실

1. 노트북 Bluetooth를 켠 후 컨트롤러 및 OBDII `00:10:CC:4F:36:03` 발견.
2. 최초 광고에는 FFF0만 보였지만 연결 후 SPP UUID `00001101-0000-1000-8000-00805f9b34fb`도 확인됐다. BLE와 Classic을 모두 제공하는 장치다.
3. 최초 Classic 연결은 `br-connection-key-missing`으로 실패. PIN 입력 후 페어링 성공. 사용자도 숫자 확인창을 확인했다고 알렸다.
4. BlueZ Profile1으로 Classic SPP 스트림 연결 성공. ATI 응답은 `ELM327 v1.5`다. 이 문자열은 실제 정품 칩이나 전체 명령 지원을 보증하지 않는다.
5. ATCSM1은 `?`로 거부돼 기본 캡처 도구는 설계대로 모니터 시작 전에 중단했다.
6. 별도 실험에서 ATD로 기본 설정 복원 후 ATMA 모드 진입을 확인했다. 이 경로는 제조사 문서의 기본 silent 동작에 의존했으며 복제 장치의 전기적 송신 유무를 계측 검증하지는 않았다.
7. 세 차례 10초 모니터링에서 파싱된 CAN 프레임은 모두 0개다. 전체 수신 필터 `ATCF000`, `ATCM000` 적용과 PID 조회 후 모니터링에서도 결과는 같았다. ATDPN은 `6`을 반환했다.
8. 경로 확인을 위한 표준 PID 요청 2개는 정상 응답했다.

| 요청 | 응답 | 해석 |
|---|---|---|
| 010D | 7E8 03 41 0D 00 | 0 km/h |
| 010C | 7E8 04 41 0C 00 00 | 0 rpm |

## 세션별 근거

원시 로그는 Git 제외 대상인 `captures/`에 보관한다.

| 폴더 | 결과 |
|---|---|
| baseline-classic-01 | 페어링 전 연결 실패, 차량 요청 없음 |
| baseline-classic-02 | Classic 성공, ATCSM1 거부, 모니터 미시작 |
| baseline-classic-03-default-monitor | 기본 설정 기반 10초 ATMA, 프레임 0 |
| baseline-classic-04-all-filter | 전체 필터 허용 10초 ATMA, 프레임 0 |
| classic-reference-01 | 속도·RPM 각 1회 조회 정상, 이후 10초 ATMA 프레임 0 |

PID 응답은 raw.jsonl에 있으며 frames.csv는 모니터 구간 프레임만 기록하므로 0개다. 종료 직후 STOPPED 및 프롬프트는 의도한 모니터 종료 응답이다.

## 결론과 미확정 사항

- Classic SPP의 실제 사용 가능 여부는 확인됐다. 두 무선 방식의 성능 비교는 하지 않았다.
- 질의·응답 경로는 동작한다. 지금 OBD 경로에서 방송 CAN을 받을 수 있다는 가정은 입증되지 않았다.
- 게이트웨이 또는 OBD 버스 구성, 어댑터의 불완전한 모니터 구현 등 원인을 아직 구분하지 못했다. 메시지가 없다는 결과만으로 차량 전체에 방송이 없거나 스니핑이 불가능하다고 단정하지 않는다.
- 수신 프레임이 없으므로 공개 DBC 적용이나 신호 의미 검증을 진행한 것으로 보고하지 않는다.
- ATCSM1 미지원은 로그에 남겼다. 일반 도구의 응답 검증을 무조건 완화하지 않았으며 기본값에 의존한 실험은 별도 세션으로 분리했다.
