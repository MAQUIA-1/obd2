# 현재 수집 데이터 기반 주행 상태 추정

2026-11-19. 기존 미확보 동력 플래그 기반 설계를 이 문서로 대체한다. 구현은 `src/features/drive-status/state-machine.ts`, 웹 화면은 D에서 주행 방식이 추정됐을 때 상단 중앙에 표시한다. 웹앱은 연결한 차량에서 받은 입력을 사용한다.

## 1. 범위와 입력

상태머신은 현재 `tools/obd_poll.py`가 해석하는 **차속·셀렉터 기어·엔진 RPM·HV 배터리 전류** 네 항목만 받는다. 제동 페달, 모터 토크, 엔진 토크, 클러치, 발전·회생 플래그는 입력 항목에 포함하지 않는다. 전압은 수집 가능하지만 현재 추론에는 필수가 아니므로 사용하지 않는다.

- 기본 사실: 이동 여부, RPM상 엔진 회전 여부, 속도 추세.
- 추정: 전류의 크기·방향과 엔진 회전·속도 추세를 조합해 EV/엔진/복합/타력/회수/충전을 판단.
- 중앙 문구는 D에서 EV 주행, 엔진 주행, 복합 주행, 타력 주행 중 하나가 확인된 경우에 표시한다. 기본 관측 상태와 충전·회수 결과는 상태머신 내부에 남으며 중앙은 비어 있다. RPM>0을 엔진의 바퀴 구동 토크나 연소 확인으로 취급하지 않는다.

각 샘플은 `{value, at, verified}`다. `at`은 로컬 단조 수신 시각(ms), `verified`는 파서가 항목/형식/유효값을 확인한 표시다. 센서 정확도나 전체 주행 상황을 실측 검증했다는 뜻이 아니다. 미래·역순·무효·미수신은 정상값으로 대체하지 않는다.

## 2. 전류와 속도 추세의 의미

전류 방향은 정책 `dischargeSign`으로 정규화한다. 현재 초기 가정은 **양수 방전, 음수 충전**이며 반대 부호도 정책으로 지원한다. 실차 정차 로그에서 부호를 독립 검증한 것은 아니므로 확정 제원으로 기록하지 않는다.

전류 1.3A와 같은 작은 사용을 구동으로 과대 해석하지 않도록 deadband를 둔다.

| 항목 | 초기 설정 | 의미 |
| --- | --- | --- |
| 큰 방전 진입 | +5A 이상 | 배터리 사용이 보조 부하 수준보다 크다고 보는 추정 기준 |
| 큰 충전 진입 | −5A 이하 | 뚜렷한 충전으로 보는 추정 기준 |
| 작은 전류 | 절댓값 3A 이하 | 작은 사용/충전. 무소비·토크 0을 의미하지 않음 |
| 전류 이력 유지 | 3~5A 사이 | 이전 큰 방전/충전이면 유지, 최초 진입이면 미확인 |
| 상세 주행 추정 최소 속도 | 5km/h | 크리프·속도 양자화 구간에서 추정을 억제 |

이 수치는 **보정 가능한 초기 휴리스틱**이며 LF 실측으로 확정된 경계가 아니다. 히터·에어컨·기타 부하가 크면 전류만으로 구동 보조와 구분할 수 없다. 화면 배지 유무와 무관하게 추정의 한계로 남긴다.

속도 추세는 새 속도 패킷의 최대 3초 이력을 사용한다. 최소 750ms 간격의 기준값 대비 2km/h 이상 변화하고 평균 가속도 절댓값이 0.2m/s² 이상일 때 가속/감속으로 분류한다. 나머지는 정속 범주다. 최초 샘플·긴 공백·기어 변경·재연결에서는 추세를 미확인으로 시작한다. 정수 km/h의 1단계 흔들림을 감속으로 처리하지 않는다.

## 3. 판정표와 우선순위

상세 추정은 D, 유효하고 시각이 맞는 네 입력, 이동 중 최소 속도, 유효한 속도 이력을 전제로 한다. 아래 ‘방전/충전/작음’은 위 deadband 판정이다.

| 관측 | 표시 | 구분 |
| --- | --- | --- |
| 연결 종료 | 차량 미연결 | 입력 상태 |
| 속도/기어 없음·오래됨·시각 불일치 | 정보 대기 | 입력 상태 |
| P인데 이동 | 상태 확인 | 입력 모순 |
| 속도 0 + RPM 0 또는 RPM 미확인 | 정차 중 | 관측 |
| 속도 0 + RPM 있음 | 정차 · 엔진 회전 | 관측 |
| 속도 0 + RPM 있음 + 충전 | 정차 충전 | 추정. 엔진 발전의 정확한 경로는 주장하지 않음 |
| N에서 이동 | 중립 이동 | 관측. 동력원 추정 제외 |
| R에서 이동 | 후진 중 | 관측. 방향은 기어 의도 기준 |
| 이동 + RPM 0 + 방전 + 정속/가속 | EV 주행 | 추정 |
| 이동 + RPM 있음 + 방전 + 정속/가속 | 복합 주행 | 추정. 전류 일부가 부하일 수 있음 |
| 이동 + RPM 있음 + 작은 전류 + 정속/가속 | 엔진 주행 | 추정. 모터 기여 0의 확정이 아님 |
| 이동 + RPM 0 + 작은 전류 + 정속 | 타력 주행 | 추정. 약한 구동·경사·낮은 저항과 구분 미완료 |
| 감속 + RPM 0 + 충전 | 에너지 회수 | 추정. 페달을 밟았는지·마찰제동 병행 여부는 주장하지 않음 |
| 충전 중 이동, 위 회수 조건 아님 | 주행 중 · 충전 | 추정. 엔진 발전과 회생을 억지로 구분하지 않음 |
| 감속 + 작은 전류 또는 방전 | 감속 중 | 관측. 엔진 제동/마찰제동/경사로 단정하지 않음 |
| 상세 조건 불충족, RPM만 유효 | 엔진 정지 주행 / 엔진 회전 주행 | 관측 |
| 이동만 유효 | 주행 중 | 관측 |

에너지 흐름 전용 신호 없이도 상관관계로 유용한 상태를 추정한다. 다만 ‘마찰제동’, ‘혼합제동’, ‘엔진 제동’, ‘엔진 발전+모터 구동’은 분리할 근거가 부족하므로 상태 목록과 입력 예시에서 삭제했다. 감속+충전에서도 엔진이 돌면 발전 충전이 섞일 수 있어 ‘회수’로 확정하지 않고 내부적으로 충전 주행으로 분류한다. 저전류 감속을 자동 타력주행으로 분류하지 않는다. 마찰 브레이크일 수 있기 때문이다.

## 4. 전환 안정화와 입력 품질

- 유효기간 3초, 동시 판정 샘플 간 최대 시각차 1.5초. 전류·RPM을 함께 쓸 때 네 항목 전체의 시각 정합성을 확인한다.
- 정차 진입 ≤0.5km/h, 이동 진입 ≥2km/h. 그 사이에서는 이전 이동 상태를 유지하며 최초에는 미확인이다. 1km/h 크리프의 정밀 판정은 미완료다.
- 상태머신은 기본 관측 상태를 즉시 반환한다. 상세 추정은 같은 후보가 최소 700ms, 2회의 독립 수신에서 유지될 때 반환한다. 속도 이력 준비 시간까지 포함하면 보통 2~3초 이상 걸릴 수 있다.
- 독립 수신은 판정에 사용한 네 샘플 중 가장 오래된 시각이 전진한 경우다. UI 프레임 수나 빠른 속도 PID만으로 확인 횟수를 늘리지 않는다.
- 기존 추정 근거가 사라지면 즉시 기본 관측 상태로 복귀한다. 새 추정을 확인하는 동안 중앙 문구는 비어 있다.
- 정차는 주행 추정보다 우선한다. 정차 중 RPM이 있어도 자동 ‘충전’은 아니며 충분한 충전 전류가 필요하다.
- 연결 종료·기어 변경은 속도 이력, 전류 히스테리시스, 전환 후보를 초기화한다. 재연결에서는 이전 연결의 오래된 샘플을 거부한다.

실차 폴링은 기록상 속도 약 0.65초, RPM 약 1.12초, BMS 약 1.30초 간격이었다. 이 상태는 운전 보조용 요약이며 브레이크 작동 표시나 제어 신호가 아니다.

## 5. 화면과 개발 중 검증

`ECU 파서 / 로컬 미리보기 입력 → 시각 포함 Snapshot → 상태머신 → D 주행 방식 4종 필터 → 한 줄 UI`

디버그의 ‘주행 입력 예시’는 RPM·전류·차속만 설정한다. EV·회생 상태를 직접 강제하거나 가짜 모터/브레이크 플래그를 주지 않는다. 감속 예시는 매 합성 수신마다 차속을 줄이고 실제 속도 store를 사용하므로 속도계·바닥 이동과 판정 이력이 일치한다. 정지하면 감속이 끝나고 정차 상태가 된다.

RPM·전류 수치도 상태 계산과 같은 예시에서 표시한다. 개발용 샘플은 1초마다 생성하며 같은 snapshot의 250ms 재평가는 새 확인으로 세지 않는다. 실차 모드는 [Web Serial 폴링](OBD_연동.md)으로 받은 샘플을 사용한다.

## 6. 검증과 근거

테스트는 네 입력만으로 EV/복합/엔진/타력/회수/충전 추정, 감속과 제동의 구분, 전류 deadband·반대 부호, 시각차·신선도·역순, 정차 우선, 속도 흔들림, 연결 복구, 개발용 샘플의 입력 필드 제한을 검증한다. 통과는 분기·일관성 검증이며 도로에서의 추정 정확도 검증은 아니다.

- [실차 폴링 수집 결과](Classic_폴링_수집_결과.md), `tools/obd_poll.py`: 확보 데이터, 시험 범위, 갱신 간격.
- [현대 에너지 흐름 설명](https://ownersmanual.hyundai.com/ivi/STD_GEN5W/AVNT/EU/English/hybrid.html): 충전과 구동이 함께 존재할 수 있고 엔진 발전·회생이 별개라는 배경. LF PID 지원 또는 현재 휴리스틱의 정확도를 증명하지 않는다.

실측과 추정의 구분, 표의 규칙, 임계값은 프로젝트 설계이며 순정 하이브리드 상태 표시 알고리즘의 재현이 아니다.
