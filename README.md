# OBD Dashboard

2015년식 LF 쏘나타 하이브리드의 OBD 데이터를 표시하는 React 웹 대시보드. 삼성 스마트폰 Chrome과 DeX 세로 모니터가 대상이다.

현재는 **차량 화면 프로토타입** 단계다. 사용자 제공 LF 쏘나타 GLB를 로딩하며 P의 회전형 개러지·R의 버드아이뷰 후방 점선·D의 중앙 정후방 주행 시점을 확인할 수 있다. 화면의 수치는 데모 값이고 실제 OBD 통신은 아직 구현하지 않았다.

오른쪽 아래 플로팅 버튼에서 디버그 패널을 연다. P/R/N/D 강제 전환, 조향 슬라이더와 중앙 복귀는 이 패널에만 있다. Escape 또는 닫기로 패널을 닫으며 데모 상태는 유지한다. 점선·앞바퀴·바닥은 LF 제원 기반의 같은 저속 운동 모델을 사용한다. 국내 차량 조향비와 실제 주차 궤적 보정은 미완료다. [제원 출처와 계산식](research/차량_운동_모델.md)을 참고한다. 속도는 디버그 패널에서 R/N/D 상태로 전환한 뒤 조절한다. 속도에 따라 3D 바닥 패턴이 흐르고, 0km/h 또는 P에서는 멈춘다. P로 전환하면 데모 속도도 0으로 초기화한다.

## 실행

Node.js 22 계열의 22.13 이상을 기준으로 한다. Node 24 또는 26 이상도 도구의 지원 범위에 포함된다. `.nvmrc`는 현재 검증한 Node 22 계열을 사용한다. npm을 사용하고 `package-lock.json`을 함께 관리한다.

```sh
npm ci
npm run dev
```

개발 서버가 출력하는 로컬 URL을 브라우저에서 연다.

## 개발 명령

| 명령 | 용도 |
|---|---|
| `npm run dev` | Vite 개발 서버 |
| `npm run typecheck` | 앱·설정 파일 TypeScript 검사 |
| `npm run lint` | ESLint, 경고도 실패로 처리 |
| `npm test` | Vitest 감시 모드 |
| `npm run test:run` | Vitest 1회 실행 |
| `npm run build` | 타입 검사 후 정적 파일을 `dist/`에 빌드 |
| `npm run preview` | 빌드된 정적 파일을 로컬에서 확인 |
| `npm run check` | 타입·린트·Vitest·빌드 순차 확인 |

조향 가이드·차량 운동·유리 재질·바닥 이동·카메라 전환의 자동 테스트가 있다. 이후 실제 OBD 파서·데이터 상태·모드 전환에 테스트를 추가한다. 기존 Python 도구와 `tests/`는 별도로 유지한다.

## 스택

- React 19 / TypeScript 6 / Vite
- Tailwind CSS 4 + CSS 변수
- Three.js / React Three Fiber 9 / Drei
- Motion for React / Zustand
- Vitest / ESLint
- Web Serial 타입 선언 설치. 실제 통신은 후속 구현

`src/app/App.tsx`와 `src/styles/index.css`가 화면 진입점이다. `src/features/vehicle-scene/`는 모델·카메라·가이드를, `src/features/debug/`는 디버그 패널을 담당한다. 데모 제어는 `src/stores/demo.ts`에서 관리한다. Web Serial 어댑터는 아직 구현하지 않았다.

데스크톱 Chromium에서 모델 표시, 조향·중앙 복귀, 화면 전환, 디버그 패널 기본 숨김·열기/닫기·Escape 포커스 복귀를 확인했다. 360×800, 430×932, 720×1280에서 가로·세로 넘침과 런타임 오류가 없었다. 검증은 소프트웨어 WebGL 렌더러에서 수행했으며 실제 스마트폰·DeX 성능 검증은 남아 있다. 3D 코드는 지연 로딩하지만 빌드 시 500kB 초과 청크 경고가 남아 있다.

## 실제 차량 연결 환경

실제 통신은 Android Chrome의 Web Serial / Bluetooth Classic SPP로 구현할 예정이다. 목표 스마트폰에서 시험할 때는 HTTPS가 필요하다. 노트북의 개발 서버를 네트워크 IP의 HTTP로 여는 것만으로는 보안 컨텍스트 조건을 충족하지 않는다. 기본 개발 서버는 HTTPS를 설정하지 않았으며 실제 스마트폰·DeX 연결은 아직 검증 전이다.

설치 중 별도 백엔드·DB는 구성하지 않았다. `captures/` 원시 로그와 `research/sources/`는 기존과 같이 Git 제외 대상이다.

TypeScript는 템플릿의 7 대신 ESLint TypeScript 플러그인의 지원 범위에 맞는 6.0.3을 사용한다. 설치된 구체 버전은 package-lock.json에 고정돼 있다.

P에서는 차량 장면을 드래그해 회전시킬 수 있고 점선은 표시하지 않는다. R에서는 차량 위 고정 시점과 뒤쪽 점선만 표시하며, D에서는 정후방 추적 시점으로 고정한다. 조향값은 디버그 패널에서 변경한다.

원본 모델의 두 유리 재질은 검정 RGB 텍스처와 불투명 설정을 갖고 있어, 로딩 시 투과·투명도·깊이 쓰기 설정을 보정한다. 원본 GLB는 수정하지 않는다. `src/features/vehicle-scene/model-materials.ts`에서 표시용 재질을 생성하며 차체·타이어 텍스처는 유지한다. 데스크톱 Chromium에서 창문 안쪽이 보이고 런타임 오류가 없는 것을 확인했다.

바닥은 정적인 3D 평면 위에 반복 패턴을 그리는 셰이더로 구현했다. 카메라 원근에 맞춰 보이고 멀어질수록 옅어진다. D/N은 전진, R은 후진으로 가정하며 차속을 m/s로 변환해 실제 배율로 이동한다. 바닥과 점선·앞바퀴는 동일한 곡률을 사용한다. N의 실제 진행 방향과 타이어 미끄럼은 아직 반영하지 않는다. 프레임 시간으로 이동량을 계산하고 탭 복귀 시 큰 점프를 제한한다. OS에서 모션 줄이기를 요청하면 바닥 이동을 끈다. 현재 입력은 명시적인 데모 값이며 실차 데이터는 아직 연결하지 않았다.

## 모드별 정보 구성

속도와 세로 PRND는 왼쪽 위·오른쪽 위 위치를 유지한다. km/h는 속도 숫자 오른쪽에 붙이고 N/D의 RPM·HV 배터리 전류는 속도 바로 아래에 숫자·단위만 나란히 표시한다. RPM은 표시 확인을 위한 1,500rpm 목업이며 나머지 정적 값은 저장된 정차 수집 예시다.

- P: 속도·RPM·전류는 숨기고 회전형 차량과 하단 연료 / 배터리 / 외기온 세 항목을 표시한다.
- R: 속도·PRND·버드아이뷰·후방 점선과 하단 조향각만 표시한다.
- N/D: 하단 연료 / 배터리 / 냉각수온 세 항목을 같은 배치로 표시한다. 외기온은 이 세 항목과 분리해 PRND의 D 아래에 간격을 두고 26px 숫자와 °C 단위만 표시한다. N/D는 기어 선택 표시를 제외한 정보 구성과 배치가 같다. HV 전압은 메인에 표시하지 않는다.

회전수와 전류는 정확한 출력 전력을 뜻하지 않으며 작동 정도를 읽는 지표다. 실차의 충방전 부호·추정 정확도·READY는 아직 검증 전이다. 상태 문구는 속도·기어·RPM·HV 전류만 조합하며 EV/엔진/복합/타력/회수/충전을 추정한다. 화면에는 상태 문구만 표시하며 추정 배지는 붙이지 않는다. 마찰·혼합·엔진 제동은 구분하지 않는다.

현재 값은 데모이며 정차 수집 원본의 RPM 0과 화면 목업의 1,500rpm은 구분한다. 모든 강제 상태/속도/조향 조작은 디버그 패널에만 있다.

상단 P/R/N/D 목록은 모든 모드에 항상 표시하고 현재 기어만 큰 진한 글자로 강조한다. 각 글자의 슬롯 크기는 고정해 기어 변경 시 목록 위치가 흔들리지 않도록 했다. 모드별 속도계·보조 정보 구성은 유지한다.

디버그에서 N(중립)도 선택할 수 있다. N은 중앙 정후방 구도와 큰 속도계를 유지하고 상단 N을 강조한다. 중립에서도 차가 움직일 수 있으므로 속도 입력은 유지하며, 0km/h일 때만 바닥 흐름을 멈춘다.

## 화면 공통 규칙

모든 모드는 같은 높이의 계기 영역과 차량 영역을 사용한다. 속도 숫자는 80~104px이며 오른쪽 위 P→R→N→D 세로 목록의 선택 기어는 48px다. 슬롯 크기와 위치는 모드 전환 중에도 유지한다. 최대 너비는 680px다. P 하단은 연료·배터리·외기온, N/D 하단은 연료·배터리·냉각수온 세 항목으로 정렬하고 R에서는 같은 영역에 조향만 표시한다.

바닥은 1.2m 간격의 `+` 패턴이며 속도와 조향에 따라 이동·회전한다. 차량에서 멀어질수록 흰 배경에 섞이도록 페이드하며, P에서는 더 옅게 표시한다. D/N에서는 전방 페이드 거리를 약 8m에서 24m로 늘리고 모드 전환 시 서서히 적용한다. 후진 조향 점선은 별도 요소로 유지한다.

카메라 전환은 0.85초의 고정 시간 보간을 사용한다. 시선 방향과 거리·주시점을 함께 보간하며, 화면 안에 차체 전체를 강제로 맞추는 거리 보정이나 중간 후퇴는 하지 않는다. P의 기본 시점은 앞코가 왼쪽을 보는 대각선이며 시선 중심을 약간 보정했다. R은 정확한 수직 방향을 사용한다. 전환 중에는 개러지 회전 조작을 잠시 끄고 P 도착 후 다시 켠다. 빠르게 모드를 다시 바꾸면 현재 표시 위치에서 새 목적지로 전환한다. 모션 줄이기 설정에서는 즉시 전환한다.

현재 렌더링은 흰 배경·밝은 무광 도장·반사 하이라이트 없는 유리·옅은 접지 그림자를 사용한다. 노출은 1.3, 접지 그림자 농도는 0.14다. 실사 스튜디오 환경 반사는 사용하지 않는다. 차체에는 얇고 옅은 회색 외곽선을 추가했다. 유리와 바퀴에는 외곽선을 추가하지 않으며 원본 모델과 텍스처는 보존한다.

정적 표시값은 `research/fixtures/verified-poll-examples.json`의 정차 예시를 바탕으로 `src/features/vehicle-info/demo-readings.ts`에 모아 두었다. RPM은 화면 확인용 1,500rpm 목업이다. 하단에 데모임을 표시하며 실제 차량 연결은 아직 구현하지 않았다. 차량 상세 버튼·패널은 표시하지 않는다.

주행 상태 판정은 [상태머신 설계](research/주행_상태머신.md)에 정리했다. `src/features/drive-status/`는 현재 파서가 제공하는 속도·기어·RPM·HV 전류 네 입력만 사용하고 신선도·속도 추세·전류 deadband·전환 확인을 처리한다. N/D 상단 중앙에 연결했고 실제 통신은 아직 없다. 디버그의 ‘주행 입력 예시’는 수치만 바꾸며 동력·제동 플래그를 생성하지 않는다. 감속 입력은 속도계·바닥과 같은 차속을 감소시킨다. 전류 부호와 5A/3A 경계는 조정 가능한 초기 가정이며 실차 보정값으로 취급하지 않는다.
